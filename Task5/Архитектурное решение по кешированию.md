
## Мотивация

Сейчас система передаёт существенное количество данных основанных на "стандартных" решениях
Бизнес предлагает пользователям типовые продукты, но перед каждым заказом происходит полный расчет

Внедрение кэширования должно дать существенный прирост в производительности и разгрузить ключевые компоненты

## Предлагаемое решение

1. Реализация кэша на клиенте интернет магазина

Пользователи интернет магазина могут выбирать стандартные предложения товаров.
Цены на них не должны меняться слишком часто.
Вполне вижу реализуемым HTTP кэширование как для списков предлагаемых товаров, так и для их основных параметров (включая цену)
Можно настроить более длительный max-age для карточек товаров (модели, параметры товара)
И более краткосрочный для таких параметров как цена

2. Реализация кэша для MES API

Для внешних пользователей существует какого-либо UI. Поэтому предлагаю использовать серверное кэширование 
Для операторов есть UI но клиентское кэширование для него неактуально, так как всегда должна отображаться только актуальная информация по списку заказов

Паттерны для реализации:
 - Список заказов со статусами для операторов - Write-Through
Гарантирует, что кэш всегда актуален: обновляется при изменениях на сервере

Сложности могут возникнуть с инвалидацией:

|Тип|Уместность|Пояснение|
|--|--|--|
|Временная инвалидация|не подходит|нужны максимально актуальные статусы|
|Программная инвалидация|подходит|подходит, но вероятно труднее реализуема|
|По ключу|частично|возможно попробовать реализовать только обновление нужны статусов|
|На основе изменений|подходит|соответсвует логике|
|На основе запросов|частично|изменения инициируются не только запросами|


 - АПИ для внешних пользователей - Refresh-Ahead
MES расчитывает параметры по стандартным предлагаемым товарам сохраняя их по ключу (идентификатору товара)
По мере необходимости заменяя их обновленными данными.
Задержки для пользователей будут минимальными
