
## Мотивация

Сейчас наша ситема - черный ящик. Мы не знаем, что происходит в каждом сервисе

Необходимо отслеживать состояния заказа и общую работоспособность каждого компонента.

При существовании логов сократится время на вычисление причин потери работоспособности и время на восстановление

## Примерный список логов

- уровень INFO
1. Создание заказа (дата и время, параметры, инициатор )
2. Изменение статуса заказа (дата и время, параметры, инициатор )
3. Запуск/остановка сервиса (дата и время, парметры запуска-остановки)

- уровень WARN

1. Попытка повторного создания заказа (дата и время, параметры, инициатор )
2. Изменение статуса заказа (дата и время, параметры, инициатор )


- уровень ERROR

1. Сбой сервиса (дата и время, параметры, причина)
2. Сбой вызова метода / другого сервиса (дата и время, параметры, инициатор, причина)

## Предлагаемое решение

Первочередная настройка логов для API сервисов, также возможно для брокера

- настройка RBAC 
- доступ только административным пользователям

- хранение активного лога в промежутке времени (например сутки)
- возможно настроить архивирование лога при необходимости длительного хранения


Базово возможна настройка логов просто как текстовых log файлов для каждого сервиса
Дальнейшее развитие - настройка ELK Elasticsearch плюс визуализация на Kibana, но это решение на перспективу
